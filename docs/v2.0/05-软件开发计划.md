## 5. 阶段 A3:硬件接入准备(按需启动)

A3 只做**接口边界**的准备与验收,不做量产计划、不做固件开发排期。三项边界要求(规范细节见 `09-设备能力与硬件接入规范.md`):

| # | 边界 | 要求 | 验收 |
|---|---|---|---|
| A3-1 | Transport 实现 | 新增传输通道(BLE/Wi-Fi/USB)须实现 Transport 抽象(accept/receive_text/send_text/close,09 §3);协议消息零变更 | 既有协议级测试套件(A1-7)在新 Transport 实现上通过 |
| A3-2 | capabilities 上报 | 设备经 `device.hello` 上报 capabilities(08 §2.1,可选);主机只登记不消费、不落库;未知字段必须被忽略 | 缺失/未知字段不影响连接与既有功能(前向兼容实测) |
| A3-3 | GPIO 键语义映射 | 实体按键 + 短/长按手势映射到物理键 action/page_up/page_down 的语义动作(09 §2),按键处理在端侧;状态机与业务不区分事件来源 | 三枚物理键行为与虚拟工牌逐条一致(同一验收脚本) |

其他按需项(不占关键路径,不纳入 A3 边界验收):FR-10 D2 文档提取;真实办公系统适配器(前提:企业 API 可得);7 天 soak 测试;BLE 映射设计(未启动,见 README §5)。

## 6. 硬件接入前必须保持的接口边界

以下边界是软件主线的架构约束,任何任务卡不得破坏(治理见 04 §3/§4):

1. **核心流程单入口**:一切输入(设备录音/PC 文字/PC 录音/音频文件)只经 `core/processing` 的"转写文本 → 置信度闸门 → 路由 → 技能分发 → 结果 → 审计"流程(文本入口 `process_text`),禁止旁路(边界细节见 07 §2)。
2. **传输可替换**:`gateway/transport` 的 Transport 抽象是唯一传输触点;`gateway/manager` 只管设备身份/配对/会话/状态同步/协议语义,不碰传输 API。
3. **capabilities 只登记**:`display_profile` 仍是渲染档位的唯一权威;capabilities 主机只登记不消费、不落库。
4. **键语义统一**:端侧以 `pressKey(action|page_up|page_down, gesture)` 为唯一输入语义入口(物理键 × 手势 → 语义动作,09 §2);协议消息不变(record.start/stop、confirm.response、clarify.select)。
5. **核心层不依赖 Web 框架**:router/skills/security/audit/store/adapters/scheduler/core 不得 import FastAPI/Starlette(04 §4)。
