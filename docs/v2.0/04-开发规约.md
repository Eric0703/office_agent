## §1 工作流(规约驱动开发)

1. 一切编码从**任务卡**开始。任务卡字段:目标 / 关联 FR 编号 / 涉及文件 / 验收标准 / 估时。
2. 执行:实现 → 对照验收标准自检 → 提交 Owner 确认 → 关闭。
3. **禁止**:无任务卡的编码;超出任务卡范围的"顺手重构";引入任务卡未声明的新依赖。
4. 每个阶段结束更新相关文档,保持"文档即事实"(宪法第 9 条)。

## §2 文档同步

- 行为变更必须与文档变更同次完成,不允许"先改代码后补文档"。
- FR 编号稳定:不复用、不删除,废弃只标记。
- 协议、数据模型、技术选型变更,同步更新 02 对应章节与本规约相关表。
- v2.0 起文档**不再堆叠修订记录**:结论演进直接修改正文,文档集版本经 Owner 评审后整体推进(见 v2.0 README §4)。

## §3 协议治理

- **协议登记册(`08-端云协议.md`)是唯一事实来源**(字段级定义)。
- 新增/修改消息:先登记册,后实现;每条消息带版本号。
- 两端(Agent 主机 / 虚拟工牌)的类型定义必须同源:TypeScript 类型由登记册生成或手工对齐,提交时检查一致性。
- 向后兼容:旧字段不删除,只标记废弃;**接收方必须忽略未知字段**(前向兼容,含 device.hello 的 capabilities 及其子字段)。

## §4 依赖与适配层

- 02 §3.2 选型表之外的第三方依赖,引入前需 Owner 批准(说明理由与替代方案)。
- 外部服务调用(LLM/ASR/办公系统)只允许出现在适配层模块;业务代码发现直接 import 外部 SDK 即视为缺陷。
- 核心层(router/skills/security/audit/store/adapters/scheduler/core)**不依赖 Web 框架**(FastAPI/Starlette 只允许出现在 api 与 gateway/transport 边界)。
- 密钥、token 不入库:配置文件 gitignore,仓库提供 `*.example` 模板。
- API Key 一律从环境变量读取(LLM 默认 `LLM_API_KEY`);config.yaml 只保留 `api_key_env` 占位,禁写真实 Key;`.env` 必须列入 .gitignore;真实 Provider 未配置 Key 时必须显式报错,禁止静默降级为 Mock。

## §5 测试数据合规(三层黄金测试集策略)

真实办公录音难以获取且敏感,测试数据一律来自以下三层,**禁止任何真实办公录音入库**:

| 层 | 名称 | 内容 | 来源与做法 | 用途 |
|---|---|---|---|---|
| L1 | **指令合成集**(主力) | 三类意图(现场记录/任务指令/经验沉淀)各 ≥40 条,含近义变体、同名歧义、模糊表达、干扰句 | LLM 批量生成文本 → TTS 多音色合成 → 叠加办公室噪声(20/10/0 dB 三档 SNR);每条带标准答案(意图、参数、预期行为) | 路由准确率、指令执行的自动化回归 |
| L2 | **场景公开集** | 10~15 段公开中文访谈/演讲/播客音频,每段 30 秒~3 分钟,人工标注"背景/要点/结论/待办"参考答案 | 候选:WenetSpeech 访谈类子集(CC BY 4.0)、TED/TEDx 中文演讲、高校与政府公开发布讲座 | 现场记录整理(FR-05)的质量抽检 |
| L3 | **ASR 基线集** | AISHELL-1 随机抽 100 条(带标准文本) | Apache 2.0 开源语料 | WER 基线与 ASR 回归 |

噪声库:MUSAN 噪声子集 + 自录无人声办公室底噪。

合规规则:
- 仓库只提交 **L1 合成数据、各层标注文件与语料链接**;L2/L3 音频保存在本地,不进版本库、不二次分发(仅内部测试用途)。
- L2 标注中如出现真实人名,标注稿一律占位化(同宪法第 3 条脱敏要求)。
- 测试音频的生命周期与真实音频一致:测试脚本结束即清理临时副本。

## §6 测试与验收

- 每个 FR 至少对应一条自动化或脚本化验收;FR 编号出现在测试用例命名中(如 `test_fr08_idempotent.py`)。
- **合并门槛**:L1 黄金集回归通过(意图路由准确率 ≥95%,指令行为与标准答案一致);新增功能不得降低既有指标。
- 阶段验收门(Gate)未过,不进入下一阶段(宪法第 10 条)。
- 运行时数据隔离:测试一律使用临时库/临时目录,不得触碰本机 `config.yaml` 与 `data/agent.db`;禁止 mock import 污染。

## §7 代码规范

- Python 3.11+:全量类型注解,ruff 检查通过方可提交。
- Vue3 + TypeScript:组合式 API,eslint 通过;协议消息类型集中在 `src/protocol/`。
- 小步提交;提交信息格式:`类型(范围): 说明`,类型 ∈ feat / fix / docs / test / refactor。
- 注释解释 why,不复述 what;公开接口必须有 docstring。
- Mermaid 图写作规则(渲染器兼容性血泪教训):图内文本禁止未加引号的分号 `;`;消息/标签文本避免内嵌冒号与 `<` 字符;新增或修改 Mermaid 图后必须本地渲染验证再提交。

## §8 安全

- 日志不落凭据、不落完整转写文本(截断或哈希);审计日志 append-only。
- 配对 token 加密存储(只存哈希);吊销立即生效。
- 演示期第三方 LLM API 的例外,按宪法第 3 条四项条件执行。
