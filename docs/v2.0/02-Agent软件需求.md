## 1. 定位与开发策略

### 1.1 定位

Agent 软件是本项目价值的核心载体,硬件只是它的感知/呈现终端。本系统由三个软件部分组成:

| 组成 | 部署位置 | 职责 |
|---|---|---|
| **Agent 主机** | 用户个人电脑(后续可迁入企业内网服务器) | 设备接入、ASR、意图路由、技能执行、权限与风险校验、记忆与状态、审计。设备接入与 Agent 核心合并为**单进程**,降低部署与调试成本 |
| **虚拟工牌** | 旧 Android 手机 / Android 模拟器(浏览器打开) | 硬件工牌的演示替身:模拟按键录音、屏幕显示、震动与录音指示 |
| **Mock 办公系统** | 内嵌于 Agent 主机(适配层实现) | 任务、日历、笔记库的本地模拟,真实企业系统到位后经适配层替换 |

### 1.2 开发策略:软件先行(Software-First)

1. **先做 Agent,后做硬件**。在 PC + 虚拟工牌上把三个场景的体验、协议、安全机制全部验证完,再启动硬件接入。
2. **协议硬件无关**。虚拟工牌走局域网(WebSocket + HTTP);硬件阶段只替换传输层(Transport 抽象,见 09 §3),协议语义不变。
3. **一切外部依赖可 Mock**。LLM、ASR、办公系统全部走接口抽象,演示期不被企业 IT 进度阻塞。
4. **由 AI 辅助完成整体开发**(用户已指定)。

## 2. 继承的架构决策与红线(来自 01,不再重复论证)

- 逻辑上只有一个 Agent,在 PC 侧;工牌端(含虚拟工牌)不做语义理解、不持有办公系统凭据。
- 录音唯一触发方式是**人主动按键**(单键切换:点击开始/点击结束);不做任何形式的语音唤醒/自动触发。
- 工牌屏幕只承载**待办任务、定时提醒**两类卡片;不推送 IM、邮件、资讯等任何通用通知。
- 原始音频转写完成后**默认删除**;全部数据留在本地/内网。
- 有影响的操作必须过**确认回路**;全部操作留**审计日志**。

## 3. 系统架构

### 3.1 模块划分(Agent 主机,单进程)

| 模块 | 职责 | 关键设计 |
|---|---|---|
| 设备接入层(gateway) | 设备身份/配对/会话/状态同步/协议语义(manager);传输抽象(transport) | manager 不碰传输 API;Transport 抽象(accept/receive_text/send_text/close),WebSocketTransport 为当前唯一实现,未来 BLE/Wi-Fi/USB 实现同一接口(见 09 §3) |
| 核心流程(core/processing) | 承载"转写文本 → 置信度闸门 → 路由 → 技能分发 → 结果 → 审计"核心流程 | 设备录音/PC 文字/PC 录音/音频文件**共用此文本入口**(`process_text`,来源中立:不伪造设备/录音记录,records 以 source + 可空 device_id 登记;core 零推送,`ProcessOutcome` 不含投递目标,音频接收/转写在 core 外,统一投递在 app 装配层);核心层(router/skills/security/audit/store/adapters/scheduler/core)不依赖 Web 框架 |
| 音频管线 | 音频接收、完整性校验、临时存储、转写后按策略删除 | 接收即落临时区,转写成功默认立即删除 |
| ASR 适配层 | 语音转文字,输出文本 + 置信度 | 抽象接口,演示期 faster-whisper(本地)/ FunASR / 企业 ASR 服务 |
| 意图路由 | 将转写文本分流到技能:现场记录 / 任务指令 / 经验沉淀;无法识别时走兜底 | LLM 分类 + 规则兜底;分类结果带置信度,低于阈值反问;显式模式优先 |
| 技能层(Skills) | 笔记整理、每日简报、任务操作、提醒调度、经验沉淀 | 每个技能 = 提示词模板 + 结构化输出 schema + 工具调用组合 |
| 工具与适配层(Tools/Adapters) | 任务系统、日历、笔记库的统一接口;Mock 实现先行 | 接口稳定,真实 OA/日历到位后只新增适配器,不动技能层 |
| 安全层 | 指令白名单、操作风险分级、确认回路编排、权限检查 | 见 FR-09 风险分级表 |
| 状态与记忆 | 任务/提醒/设备/草稿/审计的持久化;用户偏好 | SQLite(结构化)+ 文件系统(笔记、经验卡片,Markdown) |
| LLM 适配层 | 统一的 LLM 调用接口,provider 可切换 | 演示期可用第三方 API;企业阶段切内网模型;结构化输出做 JSON schema 校验 |

**明确不引入重型 Agent 框架**:意图路由 + 工具注册表自研,核心逻辑控制在数百行内,可审计、可测试、无框架版本绑架。模块边界与目录结构的工程落地见 `07-架构设计.md` §2/§4。

### 3.2 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | Python 3.11+ | ASR/LLM 生态最全,AI 辅助开发效率最高 |
| 服务框架 | FastAPI(WebSocket + HTTP) | 轻量、自带类型校验、文档自动生成 |
| 存储 | SQLite + Markdown 文件 | 零依赖、可备份、笔记/卡片天然可读 |
| ASR | faster-whisper(演示默认,已选定 small + 固定简体 initial_prompt) | 纯本地、无数据出域、消费级 CPU 可跑 |
| LLM | 适配层抽象;原型期规则即 Mock,真实 provider 骨架预留(Key 只经环境变量) | 不被企业内网模型进度阻塞 |
| 虚拟工牌 | **Vue3 + Vite + TypeScript + vite-plugin-pwa**(用户指定栈;产物由 Agent 主机直接托管) | 零安装:旧手机浏览器、Android 模拟器均可;TS 定义协议消息类型,与登记册对齐;不引入 vue-router/Pinia/UI 组件库,状态机 + 单 store + 电子纸风格自定义 CSS |
| 配置 | 单个 YAML 文件 + CLI | 演示期不需要管理后台 |

### 3.3 端-云协议概述(硬件无关)

通道:**单条 WebSocket**(事件、指令、推送、确认)+ **HTTP POST**(音频上传)。字段级定义以 `08-端云协议.md`(协议登记册)为唯一事实来源,此处仅列消息语义:

| 消息 | 方向 | 语义 |
|---|---|---|
| `device.hello` / `device.pair.request` / `device.revoke` | 双向 | 认证 / 配对绑定 / 吊销 |
| `record.start` / `record.stop` | 工牌→主机 | 录音开始/结束事件 |
| 音频上传(HTTP `/audio/{record_id}`) | 工牌→主机 | 音频文件上传 |
| `intent.result` | 主机→工牌 | 指令执行结果(成功/失败/待确认/候选/低置信度) |
| `confirm.request` / `confirm.response` | 双向 | 风险确认请求 / 用户确认或取消 |
| `brief.push` | 主机→工牌 | 每日简报卡片 |
| `reminder.push` / `reminder.dismiss` | 主机→工牌 | 提醒卡片上屏 / 撤下 |
| `state.sync` | 双向 | 连接建立后全量同步当前卡片与状态 |
| `ack` / `error` | 双向 | 通用应答与错误(带错误码) |

设计约束:协议只描述语义,不绑定传输。硬件阶段将 WS 事件映射到 BLE/Wi-Fi/USB 的 Transport 实现即可(见 09)。

## 4. 功能需求(FR)

> 进展动态以仓库根 `PROGRESS.md` 为准。

### FR-01 设备接入与配对

- 虚拟工牌首次访问时展示配对码(6 位数字,5 分钟有效、一次性),Owner 在 CLI 执行 `agent-host pair approve <code>` 后建立绑定(device_id + token 签发,端侧持久化,devices 表只存 token 哈希)
- hello 认证校验 token 哈希(pair_required/auth_failed/revoked 三态);心跳与断线自动重连;连接状态在虚拟工牌常显
- 会话唯一:同一 device_id 仅一个活动会话——新连接认证成功即退休旧连接,旧连接之后发来的指令(record.start/clarify.select/confirm.response/state.sync.request)无业务效果;旧连接退出经身份守卫,不影响新连接登记与 capabilities(07 §2.1、08 §2.1)
- PC 端可一键吊销(`agent-host pair revoke <device_id>`),吊销即时失效并向在线设备推送 `device.revoke`;吊销后设备仅显示"请重新配对"
- 音频上传正式模式校验 X-Token;`dev_mode=auto_approve` 为原型/测试旁路,正式部署必须关闭
- 限制(范围):配对挂起态在内存,进程重启后需重新发码(未决,见 README §5)

**验收**:断网 30 秒恢复后自动重连并 `state.sync`;吊销后旧 token 立即失效。

### FR-02 录音触发与音频上行

- 虚拟工牌提供**单键切换**大按钮(模拟实体录音键):第一次点击开始录音并发 `record.start`,第二次点击停止并发 `record.stop` 且上传音频(Owner 决策,废弃"按住说话/松开发送")
- 统一输入语义:PWA 以 `pressKey(action|page_up|page_down, gesture)` 为唯一输入语义入口;虚拟物理键(电子纸画布外)与手机演示按钮同走此接口;未来实体 GPIO 按键 + 短/长按手势映射同一语义动作(见 09 §2)
- 弱网与离线:一切上传先入端侧 IndexedDB 恢复凭据(record_id 幂等),仅当对应**终态** `intent.result`(success/failed/low_confidence)到达才出队;受理(200)后页面关闭/断连,重连经 duplicate 补推恢复。错误分级:5xx/网络错误自动退避重试(2s/5s/10s,用尽则保留队列等下次重连),4xx 永久拒绝即时移除;clarify/pending_confirm 为中间态,凭据保留。补推前经归属校验(跨设备不可读);缓存淘汰/服务重启按 records 终态合成通用结果
- 录音页为**静态页**:显示"录音中"状态(PWA 触控替身按钮提示"点击结束"),**不做每秒计时刷新**(Owner 决策;刷新成本见 07 §6.2);红色录音指示由独立 LED 承担(仿真端以黑条模拟);3 分钟提醒触发时局刷一次提示文案。电子纸屏幕为纯显示区,屏内不出现"开始录音/点击结束"触摸按钮
- <2 秒的录音静默丢弃(防误触,与 01 一致)
- 防遗忘兜底:录音满 3 分钟震动/界面提醒;满 5 分钟自动停止并按正常流程上传
- 禁止语音唤醒、自动开始、后台录音(宪法第 2 条;单键切换仍是人为显式触发,性质不变)

**验收**:弱网(限速 100KB/s)下 60 秒音频上传成功率 100%(允许重试);3 分钟提醒与 5 分钟自动停止可演示。

### FR-03 ASR 转写

- ASR 适配层统一接口:`transcribe(audio) → {text, confidence}`
- 置信度阈值配置化(`asr.low_confidence_threshold`,默认 0.5);低于阈值时结果标注"转写置信度低",不强行进入指令执行
- 热词/业务词表:`asr.hotwords` 配置项,faster-whisper(≥1.1)原生 hotwords 参数直接传入;真实词表仅本机 config.yaml(不提交),`config.example.yaml` 只给匿名占位。热词仅改善识别,不改变路由/校验/确认语义
- ITN 与参数调优未做(范围未决,见 README §5)

**验收**:中文近讲 1 米、安静/办公室噪声两档环境下,转写可用率(人工抽检)≥ 90%。

### FR-04 意图路由

- 输入转写文本,输出四类之一:`field_note`(现场记录)、`task_command`(任务指令)、`experience`(经验沉淀)、`unknown`
- 用户可在录音前手动指定模式(虚拟工牌模式切换:auto/field/experience),跳过自动分类——这是准确率的兜底路径;任何情况下**显式模式优先于自动路由**
- `unknown` 不猜测执行,工牌提示"未理解,请换种说法或到电脑操作"
- **LLM 分类 + 规则兜底**(已实现):auto 模式先经 LLM 分类(四类 + 白名单指令 + 参数,JSON 结构化输出);分类置信度低于阈值(0.6)→ `unknown`(反问,不再走规则);LLM 异常/非法输出 → 回退关键词规则兜底;`task_command` 无指令名时用规则补齐,补不出 → `unknown`(不猜测执行);LLM 指令名必须在白名单内,否则按非法输出回退规则
- mock provider 语义即"规则即 Mock"(运行时纯规则路由);**第三方 LLM 运行时接入暂停**——人名/组织名脱敏与出域审计未就绪(宪法第 3 条),非 mock provider 装配即显式报错;`OpenAICompatibleProvider` 仅供合成黄金集验收测试直接调用,待后续安全任务完成脱敏与出域审计后开放(见 README §5)
- 规则护栏:完成/提醒指令只认命令式(标记/设为/提醒我/定时提醒/定时任务),陈述句("指标已经完成了""运维同学提醒")不误触写指令——安全敏感方向(误路由 task_command)在 L1 回归中为 0

**验收**:三类语料各 50 条,路由准确率 ≥ 95%;误路由到 `task_command` 的样本为 0(安全敏感方向零容忍)。验收实测经真实 LLM 跑 L1 黄金集(`--runslow` + `LLM_ACCEPTANCE=1` + `LLM_API_KEY/LLM_BASE_URL/LLM_MODEL`,见 `test_fr04_l1_regression.py`);CI 常态跑规则兜底回归(零容忍 = 0)与桩 LLM 逻辑用例。

### FR-05 现场记录整理(场景 1)

- 按模板结构化:**背景 / 要点 / 结论 / 待办**,生成笔记草稿(Markdown)
- 草稿进入"待确认"队列,PC 端可查看;用户确认后归档到笔记目录,识别出的待办转为任务草稿
- 查看与确认入口:PC 草稿工作台(`http://localhost:8000/?desk=1`,同源本机接口)查看最近处理记录(时间/状态/转写文本/置信度)与待确认草稿,笔记草稿经人工"确认归档"落盘本机笔记目录;**待办转任务草稿实现前,任何界面不得声称可生成任务草稿**
- 转写完成默认立即删除原始音频
- 转写置信度低时,草稿显著标注,提示人工补录
- 范围说明:人工确认归档已实现(`POST /desk/drafts/{id}/confirm` → 本机 `data/notes/` Markdown + drafts 置 confirmed + 审计);**待办转任务草稿未实现**(tasks 表无 draft 态,涉数据模型决策;未决,见 README §5)

**验收**:一段 3 分钟讨论录音,从松开按键到草稿生成 ≤ 60 秒;结构化字段完整率 ≥ 90%(人工抽检)。

### FR-06 每日简报(场景 2)

- 每个工作日可配置时间(默认 08:30)自动生成:今日日程、临期任务(3 天内)、日程冲突提示,3~5 条
- 触发逻辑:到点在线即生成并 `brief.push`;到点不在线则生成后暂存,连接建立经 `state.sync` 补发;若 PC 开机晚于设定时间,首次连接时补生成当日简报(与 01 §4.2 对齐)
- 数据源仅来自已授权适配器,缺源静默省略
- 范围说明:简报生成未实现(`BriefingSkill.generate` 未实现;briefings 表结构与 `state.sync` 补发通道已就绪;未决,见 README §5)

**验收**:Mock 数据下简报内容与任务/日历数据完全一致(不允许 LLM 编造条目,条目级可追溯来源 ID)。

### FR-07 提醒调度与显示(场景 2 的屏幕部分)

- **只允许两类卡片**:待办任务(到期/催办)、定时提醒(用户设定,如"15:00 提交周报")
- **页面模型**(Owner 决策,2026-07-22,方案 A):页序 = 身份首页(已连接默认页,有无待办均在)→ 待办/提醒卡(单卡一页,最高优先在前)→ 今日简报页;上翻/下翻**双向循环**;结果页短暂显示后返回原页面(详见 07 §6.1)
- 卡片生命周期:`reminder.push` 上屏 → 更新 → `reminder.dismiss` 撤下;简报页经翻页键查看
- 新建与触发:语音"新建定时提醒"直写 timer 卡(remind_at 为明确 ISO8601);到点触发为最小实现(30s 扫描到期卡并广播 `reminder.push`;触发记录仅内存,进程重启后过期未撤卡会补触发一次);语音"取消提醒"明确拒绝(未决,见 README §5)
- 完成/取消路径:PWA 列表触控勾选可完成任务(撤卡同步)或取消定时提醒;完成状态持久化并广播同步;电子纸档无触屏,以编号/项目符号列表清晰呈现
- **闭环**:任务被语音或 PC 端标记完成 → 对应卡片即时从工牌撤下("说完即消")
- 卡片持久化,重启/重连后经 `state.sync` 恢复
- 范围说明:周期性重复提醒未支持("定时提醒"= 一次性、可取消;未决,见 README §5)

**验收**:语音完成任务到卡片消失 ≤ 5 秒;主机重启后卡片无丢失、无幽灵卡片。

### FR-08 语音任务指令(场景 3)

- 白名单指令(MVP 四个):**完成任务**、**查询今日任务**、**新建简单任务**(标题+截止时间)、**新建定时提醒**(一次性、可取消的定时提醒,非周期 cron;Owner 决策 2026-07-21)
- 定时提醒的解析(相对日期+具体时间 → 明确 ISO8601)不确定时(缺日期/时间已过),须经候选确认后才写入(`remind:confirm`/`remind:cancel`);缺时间/缺内容直接失败提示,不猜测执行
- 参数抽取(任务名、时间);存在歧义(同名任务)时返回候选列表,工牌按键选择,**不猜测执行**;候选可取消(clarify 页长按主操作键):取消为完整服务端终态——不执行任何候选、审计记 cancelled、凭据可出队,断线重连与 duplicate 恢复后不回到候选页(08 §2.3)
- 多任务:口语并列表达规则切分为多条待办,一律先经可编辑预览确认后才创建(`task:confirm_all`/`task:cancel`,端侧可编辑标题经 `edited_labels` 回传);切分覆盖并列词/标点、"把字句"与"X 得准备 / X 也要弄"宾语前置、"提前"子句边界;"和"、"、"不切分;无显式创建动词但有并列词+动作动词时按多任务猜,同样必须确认;"提醒我…,然后…"的提醒+任务混合句按复合预览呈现(提醒与各项待办分列),不合并为单条提醒;不要求任何固定句式;预览上限 5 条
- 写操作幂等:同一 `record_id` 重复提交不产生重复副作用
- 结果三态:成功 / 失败(带原因)/ 待确认
- 范围说明:LLM 参数抽取未接(原型期规则即 Mock);切分为规则式,无并列线索的纯陈述仍走现场记录

**验收**:白名单内指令执行成功率 ≥ 95%;同名歧义场景 100% 走候选确认;重复上传同一音频不产生两条任务。

### FR-09 风险校验与确认回路

| 风险级 | 判定 | 处理 |
|---|---|---|
| L0 只读 | 查询类 | 直接执行,记日志 |
| L1 可逆写 | 完成/新建任务 | 直接执行,记日志,结果反馈 |
| L2 不可逆或影响他人 | 发送、删除、对外操作 | `confirm.request` → 工牌显示完整后果文案 → 实体确认后执行;15 秒无操作自动取消 |

- MVP 白名单内**不开放任何 L2 指令**,但确认回路机制必须实现并演示(用一条模拟 L2 指令验证)
- 范围说明:`SecurityGuard` 核心方法(check/request_confirm)未实现;L2 模拟指令端到端演示属 A1-6 任务卡

**验收**:L2 模拟指令未经确认 0 次被执行;取消与超时路径可演示;确认记录进审计日志。

### FR-10 专家经验沉淀(场景 4)

- **D1 语音沉淀**(MVP 内):经验模式录音 → 按模板结构化(**场景 / 判断 / 依据 / 教训 / 可复用方法**)→ 经验卡片草稿 → **人工确认后入库**(Markdown 卡片目录)
- **D2 文档提取**(A3 阶段):PC 端选中文档触发提取,同样经人工确认入库
- 经验卡片可被 Agent 检索引用(处理同类问题时注入上下文)
- 范围说明:人工确认入库与检索引用未实现;D2(`ExperienceSkill.extract`)未实现,属 A3 按需项

**验收**:D1 端到端可演示;未经人工确认的卡片 0 张入库;引用时可追溯到卡片来源。

### FR-11 安全与审计

- 全量操作日志(append-only):时间、设备、转写文本(截断/哈希)、意图、工具调用与参数、风险级、确认人、结果
- 日志与普通运行日志分离,支持按时间段导出
- 配对 token 认证;虚拟工牌无独立账号体系(设备即身份,演示期单用户)
- 范围说明:日志导出 CLI 未实现(属 A2-4 任务卡)

**验收**:任意一次指令执行可在日志中完整复盘;日志不可经 API 改写。

### FR-12 虚拟工牌(演示客户端)

- 页面(与 07 §6.1 页面模型一致):身份首页(默认页,姓名/部门/二维码,不含配对码)、待办/提醒卡片页(单卡一页)、简报页(页序列末尾;上翻/下翻双向循环)、录音页(静态"录音中",无计时刷新)、候选页(全屏选择)、结果页(成功 ≤3s 自动返回;失败/未听清停留至长按返回)、确认页(L2)
- 交互:主操作键单键切换录音、模式切换(自动/记录/经验)、候选选择(上翻/下翻移动 + 主操作键短按选定/长按取消)、L2 确认(主操作键长按确认/短按取消)、震动反馈;**统一输入语义** `pressKey(action|page_up|page_down, gesture)`,虚拟物理键与演示按钮同入口(见 09 §2);普通模式为顶对齐待办应用布局,待办列表带触控勾选完成,多任务创建前展示可编辑预览确认
- 电子纸仿真:`?eink=a|b` 档位,A/B 画布统一 300×400 竖向(显示契约见 07 §6)
- PC 草稿工作台:`?desk=1` 同源本机入口(最近处理记录/待确认草稿与笔记草稿确认归档/待办任务与提醒)
- 由 Agent 主机直接托管,手机浏览器访问 `http://<PC_IP>:<port>`;PWA 可加桌面图标
- 兼容:Android 9+ 的 Chrome 浏览器;Android Studio 模拟器(麦克风用宿主机)
- 范围说明:真机 adb reverse 体验方案待做(手机浏览器 http 非安全上下文拒麦克风;未决,见 README §5)

**验收**:旧 Android 机(Android 9+)与模拟器均可完成三场景演示全流程。

### FR-13 配置与管理

- 单 YAML 配置:LLM/ASR provider、ASR 热词/业务词表(faster-whisper ≥1.1 原生 hotwords;真实词表仅本机 config.yaml,不提交)、白名单、简报时间、音频保留策略、端口、置信度阈值
- CLI:启动/停止、配对管理(approve/revoke)、Mock 数据导入;日志导出(待实现)
- API Key 一律从环境变量读取(LLM 默认 `LLM_API_KEY`);真实 Provider 未配置 Key 时必须显式报错,禁止静默降级为 Mock
- 范围说明:真实 LLM provider 未接(骨架预留)

**验收**:改配置重启生效;无需改代码即可切换 LLM provider。

## 5. MVP 范围(软件三档,与 01 对齐)

**必须做**:FR-01 ~ FR-09、FR-11、FR-12、FR-13,FR-10 的 D1 部分。

**可以砍**:
- FR-10 的 D2(文档提取)→ A3 按需项
- 说话人分离(初版"说话人 1/2"粗分)
- 多用户/多设备(演示期单用户单设备)
- 管理 Web 后台(CLI + YAML 够)
- 简报的 LLM 文采优化(模板拼装即可,杜绝编造风险)

**明确不做**(继承 01,软件视角重述):
- 任何形式的语音唤醒/自动录音触发
- IM、邮件等通用通知推送
- 虚拟工牌上的对话式交互(不做聊天 UI)
- 公网部署、多租户 SaaS 形态
- 原始音频的长期保留

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 时延 | 指令类反馈 ≤ 5s;现场记录草稿 ≤ 60s;简报生成 ≤ 30s |
| 隐私 | 音频转写后默认删除;全部数据不出本机/内网。演示期使用第三方 LLM API 属受控例外,须满足宪法第 3 条四项条件:显式开启、转写文本脱敏、审计标记、企业阶段关闭 |
| 可靠性 | 断连自动重连 + 状态全量恢复;写操作幂等;主机重启无数据丢失 |
| 可观测 | 审计日志与运行日志分离;关键链路(ASR、路由、工具调用)可追踪 |
| 可移植 | Agent 主机与虚拟工牌仅依赖局域网;无云账号绑定 |
| 分层定界 | Agent API(`/desk/*`、`/audio` 等)面向 PC、CLI 与未来软件集成;设备协议(WS)只管虚拟/实体工牌的事件、状态与结果展示 |
